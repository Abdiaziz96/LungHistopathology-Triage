The Problem

Pathology triage is a bottleneck

Every lung biopsy slide must be reviewed by a specialist. Demand grows faster than the pathologist workforce, and the first question on every desk is the same: which cases need attention first?

Volume

Slide caseloads rise year on year while specialist numbers stay flat. Backlogs delay diagnosis.

Priority

Malignant and benign cases sit in the same queue. There is no fast first-pass signal to sort them.

Trust

A model that only outputs a label is not clinically useful. Reviewers need to see why it decided.

Grad-CAM explainability

A confidence score alone does not earn clinical trust. The system back-propagates the winning class through the final convolutional block to produce a heatmap of the pixels that mattered most.

Architecture

How the pieces fit

→
REST / JSONmultipart upload, base64 response
→
FastAPI Serviceapi.py, lifespan model load
→
PyTorch ModelResNet backbone, 3-class head

Frontend

Static React bundle. Deploys to any CDN - Vercel, Netlify, or served by the API itself.

Backend

Long-running Python process holding the model in memory. Needs a container host, not a serverless function.

Model

92 MB checkpoint loaded once at startup. CPU inference supported; GPU optional.

Why not serverless? Model weights must stay resident. A cold start per request would reload 92 MB of tensors and destroy response time.

Machine Learning

Model and training

Architecture

  • Backbone - ResNet50, ImageNet pre-trained
  • Head - 3-class linear classifier, dropout 0.3
  • Input - 224 x 224 RGB tiles
  • Dataset - LC25000 histopathological image set

Training strategy

  • Phase 1 - frozen backbone, head only, higher LR
  • Phase 2 - full fine-tune, LR 1e-4, plateau scheduler

Configuration

model:  resnet50
classes: 3
dropout: 0.3
img_size: 224
batch_size: 32
epochs: 20
lr: 1.0e-4
scheduler: plateau
Two-phase training protects the pre-trained features early, then adapts the whole network to histopathology once the head has stabilised.

Deployment

Running it in production

Backend - container host

Railway via the included railway.toml. Nixpacks builds the Python environment, the health check polls /health, and on-failure restarts are capped at three.

Frontend - static CDN

Vercel or any static host. Run the Vite build, publish the output directory, point the API base URL at the backend.

Environment variables

PORT=8000
MODEL_PATH=model.pth

Health check

healthcheckPath = "/health"
healthcheckTimeout = 100
restartPolicyType = "on-failure"
Weights are not in the repo. Model files are gitignored to stay under hosting limits - the container must fetch them at build time.

What is proven, and what is not

  • Grad-CAM heatmaps generate end-to-end

Not yet established

  • Full LC25000 dataset not downloaded - no train/validation run in this workspace
  • No accuracy, sensitivity, or specificity figures measured
  • Only two test images; validation set absent
  • One image labelled adenocarcinoma was predicted benign at 91.5% - unexplained
  • Legacy backend/main.py mismatches the checkpoint and fails to load
Read this slide aloud. The system is a tested pipeline, not a validated clinical tool. Any performance claim must wait for a proper held-out evaluation.
